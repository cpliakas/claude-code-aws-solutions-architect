# Onboard

Gather shared project context for all aws-solutions-architect agents.

This skill runs a guided interview. It asks one question at a time and writes
the results to a shared memory file that every agent in this plugin reads.

## Output Location

Shared context is written to:

```
.claude/agent-memory/aws-solutions-architect/PROJECT.md
```

## Process

### Step 1: Check for Existing Context

Read `.claude/agent-memory/aws-solutions-architect/PROJECT.md` if it exists.

If it **does not exist**, proceed directly to Step 2.

If it **exists**, show the user a brief summary of what is recorded and ask:

> "Shared project context already exists. Would you like to:
>
> (a) Update specific sections -- I'll ask which sections to replace and re-run
>     only those questions. All other sections are preserved unchanged.
> (b) Start fresh -- I'll run the full interview and replace the entire file
>     when complete. If you abandon the interview before finishing, the original
>     file is left unchanged.
> (c) Skip -- keep the existing context as-is."

**If the user chooses (a):**

Show the list of sections in the existing file and ask: "Which sections would
you like to update?" Re-ask only the corresponding questions, then merge the
new answers into the existing file by replacing only those sections. Sections
not selected are preserved verbatim. Any content in the file that does not
correspond to a template section must also be preserved verbatim.

**If the user chooses (b):**

Proceed to Step 2. Write the file only after the full interview completes in
Step 3. If abandoned (user says "stop", "cancel", "never mind"), do not write
anything and tell the user: "Interview not completed. The original file is
unchanged."

**If the user chooses (c):**

Skip to Step 4.

### Step 2: Project Context Interview

Introduce yourself before asking anything:

> "I'll ask you a few questions about your project and AWS setup -- one at a
> time -- so the aws-solutions-architect agents have the context they need to
> give you useful advice. You can skip any question by saying 'skip' or 'not
> sure yet'."

Then ask these questions, **one at a time**, waiting for the answer before
asking the next. Use multiple-choice options where shown.

**Q1 -- Project overview**

> "What is this project? Give me a one or two sentence description of what it
> does and who uses it."

**Q2 -- AWS account structure**

> "How is your AWS account set up?
>
> (a) Single account for everything
> (b) Separate accounts for dev/staging/prod
> (c) AWS Organizations with multiple accounts
> (d) AWS Control Tower landing zone
> (e) Other -- I'll describe it"

**Q3 -- Primary AWS services**

> "What are the primary AWS services this project uses? List the main ones.
> (e.g., 'ECS Fargate, RDS PostgreSQL, S3, CloudFront, SQS')"

**Q4 -- Deployment tooling**

> "What do you use to deploy and manage AWS infrastructure?
>
> (a) AWS CDK
> (b) CloudFormation (raw templates)
> (c) Terraform
> (d) AWS SAM
> (e) Mix of the above -- I'll describe it
> (f) Manual / Console
> (g) Other -- I'll describe it"

**Q5 -- Environment topology**

> "What environments do you have, and which AWS regions do you deploy to?
> (e.g., 'dev/staging/prod in us-east-1, with DR in us-west-2')"

**Q6 -- Compliance requirements**

> "Are there compliance requirements the agents should keep in mind?
>
> (a) SOC2
> (b) HIPAA
> (c) PCI DSS
> (d) FedRAMP
> (e) Multiple -- I'll list them
> (f) None / not yet
> (g) Other -- I'll describe it"

**Q7 -- Current pain points**

> "What are your current pain points or focus areas with AWS? For example:
> cost management, security posture, scaling challenges, migration plans,
> operational complexity.
>
> (Skip if nothing specific comes to mind)"

### Step 3: Write Shared Context

After collecting all answers, write the following file. Omit any section where
the user skipped or had nothing to say.

```markdown
# Project Context

> Generated by /onboard. Update by re-running /onboard or editing this file.

## Project Overview

- **Description:** [from Q1]

## AWS Environment

- **Account Structure:** [from Q2]
- **Environments:** [from Q5]

## AWS Services

[from Q3 -- use bullet points if multiple items]

## Deployment Tooling

[from Q4]

## Compliance Requirements

[from Q6, or omit section if skipped]

## Current Focus Areas

[from Q7, or omit section if skipped]
```

Create the directory `.claude/agent-memory/aws-solutions-architect/` if it does
not exist, then write the file.

### Step 4: Summary and Next Steps

Present a summary of what was written.

**Next steps:**

> "Setup is complete. You can now:
>
> - Ask the **solutions-architect** about AWS architecture decisions
> - Ask the **cost-optimizer** about AWS spending and optimization
> - Ask the **security-reviewer** about AWS security posture and compliance
> - Run `/well-architected-review` for a framework review of a workload
> - Run `/estimate-cost` to estimate costs for a proposed architecture
> - Run `/write-adr` to document an architecture decision"
